# AI 幻觉防御规范

| 字段 | 值 |
|------|-----|
| 版本 | 1.0 |
| 层级 | L0 |
| 包类型 | universal |
| 引入条件 | always |
| 适用架构 | 全部（含 AI 协作场景） |
| 依赖规范 | 无（AI 协作基础规则） |
| 互斥规范 | 无 |

> 本规范是 L0 跨语言通用层，定义 AI 协作编码时识别与防御幻觉的标准操作流程。
> Skill 引擎在所有 AI 辅助编码任务中自动加载。

---

## 一、什么是 AI 幻觉

**AI 幻觉** 指 AI 模型生成看似合理但实际错误的内容，包括但不限于：

- 不存在的 API、函数、库
- 错误的代码语法或类型
- 不符合业务逻辑的实现
- 不存在的文档或配置
- 引用不存在的文件路径或类名

**UNI-AHD-001** AI MUST 假定其首次输出的所有事实性内容都是可疑的，必须经过验证。 [MUST]

**UNI-AHD-002** AI MUST NOT 主动编造任何事实性内容（API 名、版本号、文件路径、配置项等）。不确定时必须明确声明"我不确定"或询问。 [MUST]

---

## 二、5 类常见幻觉模式

| 幻觉模式 | 典型表现 | 防御方法 |
|----------|----------|----------|
| **API 幻觉** | 调用不存在或参数错误的 API | 先查 API 文档 / IDE 自动完成 |
| **类型幻觉** | 字段类型/签名错误 | 运行 tsc / mypy / rustc 编译检查 |
| **逻辑幻觉** | 看起来对但逻辑错（边界、null、状态） | 单测覆盖边界 + 人工审查 |
| **路径幻觉** | 引用不存在的文件/类/模块 | grep 全仓验证存在性 |
| **配置幻觉** | 伪造或默认错的配置项 | 查官方文档 / 跑 dry-run |

**UNI-AHD-003** AI 引用任何 API、库、类、方法时，MUST 在生成代码的同一回复中标注其**信息来源**（官方文档/项目代码/不确定）。 [MUST]

**UNI-AHD-004** 当 AI 声称"这是常见做法"或"标准做法"时，MUST 提供可查证的引用来源（URL + 文档章节）。 [MUST]

## 三、4 个提示词模板（嵌入 AI 调用 Prompt）

**UNI-AHD-005** AI 辅助编码任务 MUST 在用户 Prompt 中显式包含以下 4 个降幻觉模板中的至少 1 个。 [MUST]

### 模板 1：指定技术版本

```
使用 React 18 + TypeScript 4.9 实现，不要使用未来版本的特性。
```

> **目的**：防止 AI 用未发布的 API 或已废弃的语法。

### 模板 2：指定库版本

```
使用 lodash 4.x 版本，不要使用 5.x 的新 API。
```

> **目的**：锁定依赖版本范围，避免版本漂移。

### 模板 3：限制实现范围

```
只实现用户登录功能，不需要注册、找回密码等功能。
```

> **目的**：缩小 AI 输出空间，减少幻觉面。

### 模板 4：要求验证

```
生成代码后，说明你使用了哪些 API 并标记需要验证的部分。
```

> **目的**：强制 AI 自审 + 自标疑点，便于人类 Reviewer 重点关注。

## 四、AI 生成代码验证流程

```
1. 类型检查 ──→ tsc --noEmit / mypy / rustc
       │
       ▼
2. 语法检查 ──→ ESLint / Prettier
       │
       ▼
3. 单元测试 ──→ Jest / JUnit / pytest
       │
       ▼
4. 集成测试 ──→ 验证与其他模块集成
       │
       ▼
5. 人工审查 ──→ Code Review
```

**UNI-AHD-006** AI 生成代码后 MUST 依次执行类型检查 + 语法检查 + 单测。任一失败 MUST 视为"AI 幻觉未消除"，不得合并。 [MUST]

**UNI-AHD-007** 单测覆盖 MUST 包括边界条件（null、空、极值、并发）。AI 生成的"happy path only"测试 MUST 视为不完整。 [MUST]

**UNI-AHD-008** 集成测试阶段 MUST 在真实依赖上跑（数据库、消息队列、缓存），不允许用 mock 替代所有外部依赖。 [MUST]

---

## 五、快速验证命令

```bash
# TypeScript 类型检查
npx tsc --noEmit

# ESLint 检查
npm run lint

# 运行测试
npm test

# 构建验证
npm run build
```

**UNI-AHD-009** CI 流水线 MUST 包含 `tsc --noEmit`（或对应语言的类型检查步骤）作为强制门禁，类型错误直接阻断合并。 [MUST]

## 六、AI 代码审查重点（与 code-review-checklist 互补）

**UNI-AHD-010** Reviewer 审查 AI 生成代码时 MUST 重点关注以下 5 项：

1. **API 是否真实存在**（不在 IDE 自动完成中出现的 API 视为高风险）
2. **类型是否正确**（优先信任编译器，AI 的类型注释要二次核对）
3. **边界条件**（null / 空数组 / 0 / 极大值）
4. **业务逻辑**（AI 对"为什么这么做"无法解释的代码 = 高风险）
5. **依赖来源**（AI 引入的新依赖 MUST 是 npm 官方包，不允许私有/可疑包）

---

## 七、错误处理与上报

**UNI-AHD-011** 当 AI 输出包含不可验证内容（如"应该"、"通常"、"大多数情况下"）时，Reviewer MUST 标记为"待验证"并要求 AI 给出具体出处。 [MUST]

**UNI-AHD-012** 项目 SHOULD 在 `docs/known-ai-hallucinations.md` 维护"AI 常见幻觉案例库"，记录项目历史上发生的具体幻觉 + 防御方法。 [SHOULD]
